<h1>Contributing to KryonOS</h1>

<p>
  Contributions to KryonOS are welcome. Before opening a pull request,
  please review the project documentation and existing architecture to
  understand how KryonOS is structured and how your changes fit into the project.
</p>

<h2>Areas Where Contributions Are Welcome</h2>

<p>Contributions are especially useful in the following areas:</p>

<ul>
  <li>New board support</li>
  <li>Display and touch drivers</li>
  <li>Hardware integrations</li>
  <li>JavaScript APIs</li>
  <li>JavaScript applications for KryonOS</li>
  <li>Graphics and 3D engine improvements</li>
  <li>Bug fixes</li>
  <li>Documentation</li>
  <li>Hardware testing and validation</li>
</ul>

<h2>Before Opening a Pull Request</h2>

<ul>
  <li>Review the project documentation and existing architecture.</li>
  <li>Make sure your changes are compatible with the existing KryonOS architecture.</li>
  <li>Test your changes as thoroughly as possible before submitting a pull request.</li>
  <li>Clearly describe what your pull request changes and why the changes are needed.</li>
  <li>For hardware-related changes, provide details about the hardware and testing performed.</li>
</ul>

<h2>AI-Assisted Contributions</h2>

<p>
  We do not restrict the use of AI when contributing to KryonOS. We focus on
  the quality, correctness, maintainability, and compatibility of the code,
  regardless of whether it was written by a human or with AI assistance.
</p>

<p>
  However, the pull request must be created and submitted by you. AI assistants
  should not be presented as the contributor, author, or maintainer of the pull request.
</p>

<p>
  Please review and understand all AI-assisted changes before submitting them.
  You are responsible for the code and changes included in your pull request.
</p>

<p>
  <strong>Do not add AI assistants as commit authors or co-authors.</strong>
  In particular, do not include <code>Co-Authored-By</code> trailers identifying
  an AI assistant in your commits.
</p>

<h2>Code Quality</h2>

<p>
  Contributions should prioritize clean, maintainable, and reliable code.
  Please avoid unnecessary architectural changes unless they are discussed
  and agreed upon beforehand.
</p>

<p>
  KryonOS is designed around JavaScript as its official application runtime.
  Contributions should respect this architecture and avoid introducing
  additional application runtimes without prior discussion.
</p>

<h2>Pull Requests</h2>

<p>
  Once your changes are ready, open a pull request for the KryonOS repository.
  Please provide enough information for maintainers to understand, test, and review your changes.
</p>
<p>
  Thank you for helping improve KryonOS and expand its hardware, software,
  and developer ecosystem.
</p>
