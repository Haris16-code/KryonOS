<h1>Security Policy</h1>

<h2>Reporting a Security Vulnerability</h2>

<p>
  If you discover a security vulnerability in KryonOS, please report it
  privately rather than opening a public GitHub issue.
</p>

<p>Please include:</p>

<ul>
  <li>A clear description of the vulnerability</li>
  <li>The affected component or feature</li>
  <li>Steps to reproduce the issue</li>
  <li>The potential impact</li>
  <li>Any relevant logs, screenshots, or proof of concept</li>
</ul>

<h2>Private Reporting</h2>

<p>
  Please use GitHub's private vulnerability reporting feature when available.
</p>

<p>
  If private vulnerability reporting is not available, please contact the
  KryonOS maintainers privately before publicly disclosing the issue.
</p>

<h2>Security Updates</h2>

<p>
  Security vulnerabilities will be investigated and addressed based on their
  severity and impact.
</p>

<p>
  Once a fix is available, relevant security changes may be documented in the
  release notes or changelog.
</p>

<h2>Responsible Disclosure</h2>

<p>
  Please allow the maintainers reasonable time to investigate and address a
  security vulnerability before publicly disclosing technical details.
</p>

<p>
  We appreciate responsible security research and contributions that help make
  KryonOS safer and more secure.
</p>
